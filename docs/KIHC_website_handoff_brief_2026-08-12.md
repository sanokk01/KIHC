# KIHC 웹사이트 실행용 작업지시서

문서 버전: 1.0  
작성일: 2026-08-12  
대상: 기획팀, 콘텐츠 담당자, Supabase/Netlify 운영자

> 기존 상세 문서는 보존합니다. 이 문서는 실제 작업 지시와 확인에 필요한 항목만 압축한 실행용 요약본입니다. 관리자·DB 비밀번호 원문은 포함하지 않습니다.

| 햄버거 메뉴 | 하위 메뉴·스크롤 잠금 수정 완료 | 모바일에서 모든 메뉴 선택 확인 | 기획팀 |

## 2. 우선순위별 작업 지시

### P0. 배포 전에 반드시 실행

1. **운영자**: 노출된 Supabase DB 비밀번호를 새 값으로 변경합니다.
2. **운영자**: `supabase/kihc_full_setup.sql` 전체를 Supabase SQL Editor에서 실행합니다.
3. **운영자**: Netlify에 `DATABASE_URL`, `DB_POOL_MAX`, `NEXT_PUBLIC_SITE_URL`을 등록합니다.
4. **운영자**: Netlify에서 새 배포를 실행하고 `/adminpage1/login`을 확인합니다.
5. **운영자**: 관리자 로그인, 콘텐츠 저장·수정·삭제, 로그아웃을 테스트합니다.
6. **기획팀**: 개인정보처리방침 등 법정 고지 링크의 운영 방식을 결정합니다.

완료 기준: Netlify 배포 성공, 관리자 로그인 성공, 테스트 콘텐츠가 DB와 공개 화면에 정상 반영됨.

### P1. 정식 오픈 전 확인·수정

- 관리자 연구자료·홍보자료 편집기의 날짜 입력 중복과 형식 통일
- 푸터의 개인정보처리방침·이용약관·이메일무단수집거부 전용 페이지 연결
- 관리자 설정값과 푸터·문의 페이지의 연락처 연동
- 문의 폼을 현재 `mailto:` 방식으로 유지할지 접수 시스템으로 바꿀지 결정
- 모바일 실기기 검수 및 화면별 피드백 반영
- DB 비밀번호와 관리자 로그인 비밀번호를 서로 다른 값으로 운영

### P2. 오픈 후 또는 별도 범위로 진행

- Supabase Storage 이미지 직접 업로드
- 관리자 비밀번호 변경·복구 화면
- 로그인 반복 시도 제한 및 MFA
- 문의 이력 저장·자동 접수 메일
- 홍보자료 및 연구 PDF 공개 범위 고도화

## 6. Supabase 작업 지시

### 6.1 비밀번호 변경

1. Supabase의 **Database > Settings**로 이동합니다.
2. DB 비밀번호를 새 강력한 값으로 변경합니다.
3. 관리자 로그인 비밀번호와 다른 값을 사용합니다.
4. 일반 문서·메신저·Git에 기록하지 않습니다.

### 6.2 SQL 적용

1. 작업 전 기존 테이블을 백업합니다.
2. **SQL Editor > New query**를 엽니다.
3. `supabase/kihc_full_setup.sql` 전체를 붙여 넣습니다.
4. **Run**을 1회 실행합니다.
5. 결과에서 관리자 행이 1개인지 확인합니다.
6. `password_storage`가 `scrypt hash stored`인지 확인합니다.

주의: SQL 실행 시 다른 관리자 계정과 기존 관리자 세션은 제거됩니다. 오류 발생 시 재실행하지 말고 오류 화면 전체를 전달합니다.

### 6.3 Netlify용 URI 복사

1. Supabase 상단의 **Connect**를 선택합니다.
2. **Transaction pooler URI**를 선택합니다.
3. 포트가 `6543`인지 확인합니다.
4. 새 비밀번호가 반영된 URI를 복사합니다.
5. URI는 비밀값이므로 캡처·문서·Git에 넣지 않습니다.

## 7. Netlify 작업 지시

경로: **Project configuration > Environment variables**

### 등록 변수

```text
Key: DATABASE_URL
Value: Supabase Transaction pooler 전체 URI
Contains secret values: 체크
Scope: Builds 및 Functions 또는 All scopes
Deploy context: Production 권장
```

```text
Key: DB_POOL_MAX
Value: 1
Secret: 체크하지 않음
```

```text
Key: NEXT_PUBLIC_SITE_URL
Value: https://실제-운영-도메인
Secret: 체크하지 않음
```

### 배포

1. 환경변수를 저장합니다.
2. **Deploys > Trigger deploy > Deploy site**를 실행합니다.
3. Build log에서 install, build, deploy가 모두 성공했는지 확인합니다.
4. 실패 시 비밀번호나 URI가 보이지 않도록 가린 뒤 첫 오류 메시지부터 캡처합니다.

## 8. 배포 후 확인 체크리스트

### 공개 화면

- [ ] 메인·소개·연구자료·소식·문의 페이지가 500 오류 없이 열림
- [ ] 모바일 햄버거와 모든 하위 메뉴가 열림
- [ ] 메뉴·팝업이 열린 동안 뒤 페이지가 스크롤되지 않음
- [ ] 연구자료 목록·상세·메인에 동일한 대표 이미지가 표시됨
- [ ] 공지 상세의 본문·첨부·이전/다음 글이 정상임
- [ ] 문의 폼 필수값과 메일 앱 전환이 작동함
- [ ] 푸터 이메일·전화·등록번호 문의 버튼이 작동함

### 관리자

- [ ] `/adminpage1/login`에 DB 연결 오류가 없음
- [ ] 지정 계정만 로그인 가능함
- [ ] 소식·연구자료·홍보자료·팝업 저장·수정·삭제 가능
- [ ] 초안은 공개 페이지에 노출되지 않음
- [ ] 로그아웃 후 관리자 페이지와 API 접근이 차단됨
